约定：每确认一项，把 `[ ]` 改成 `[x]` 并在后面写上确认日期。

## 三、卡片来源与丢弃归档（本轮新功能）

自动测试覆盖了函数本身的行为。**「重说」这条路径已有端到端自动覆盖**
（`tests/narrative-generate-source.test.ts` 真 import `mixology/engine`，只 mock 大模型入口与 API 配置读取），
但**回溯 / 编辑截断 / 撤回**三处仍然只有函数级测试、没有接入验证，需要在浏览器里逐条走一遍：

- [ ] **3.1 重说**：抽出一张卡后点「重说」。期望：旧回复的卡变为「归档」，
  归档原因是「来源回复已被丢弃（重说）」一类文案；新回复抽出的卡为「生效」；
  生效列表里不存在同一来源的两张卡。同时确认小票/机括记住的值照常回滚，没被这次改动带坏。
  注：这一条**已有自动测试覆盖**（`tests/narrative-generate-source.test.ts` C 走真实 `rerollMixReply` 端到端），
  但仍建议真机确认一次——自动测试里的小票与机括是空材料，真实配方在小票落账后的回滚只有浏览器能验。
- [ ] **3.2 回溯**：回溯到中间某条消息。期望：其后所有 assistant 回复抽出的卡归档；
  来源未知的卡（记忆整理/补抽历史/深度抽取产的）一张都不动。
- [ ] **3.3 编辑玩家发言（后续轮次原文齐全，可回放）**：期望一张卡都不归档
  —— 后续轮次是原地重画，消息 id 没变。
- [ ] **3.4 编辑玩家发言（后续有老轮次没存原文，不可回放被截断）**：
  期望被截断掉那些轮的卡归档。
- [ ] **3.5 继续生成 / 重新生成尾部**：期望不归档任何卡（这两条路径纯追加，不删消息）。
- [ ] **3.6 换开场白、按新滤网重洗历史**：期望不归档。
  这是**已知限制**：这两处只换正文、消息 id 不变，卡仍指向那条活着的消息。
  编辑某条助手回复的正文同理（`editMixTurn` 保留 id），也不归档。
- [ ] **3.7 撤回最后一轮**（`undoMixLastRound`）：**目前无入口，无法手测**，
  函数本身的归档行为由 `tests/card-source.test.ts` 覆盖；等 UI 接上后再补手测。
- [ ] **3.8 归档卡的恢复**：在「已归档」筛选下点「恢复生效」。期望：卡片回到「生效」、
  归档原因被清除；来自被丢弃回复的卡旁边应能看到小字提示「该卡来自已被丢弃的回复」；
  悬停在归档卡上能看到「归档原因：……」。已归档的卡不再显示 📦 按钮（重复归档无意义）。
  注意：情感卡列表只渲染前 8 条，归档的情感卡要先点「已归档」筛选才看得到。
- [ ] **3.9 竞态**：出一轮回复后立刻（在抽取还没结束时）点重说。
  期望：慢了一步落库的那张卡直接是「归档」，不会以「生效」混进上下文。
- [ ] **3.10 水位不回退**（本轮有意不做，见待办 #24）：重说后关系水位停在旧回复推上去的值，
  确认你接受这个现状；只验证「来源已消失时不再写水位」。
- [ ] **3.11 执笔生成后点重说**（本轮修复待办 #25）：在执笔面板选定报幕生成正文、正文进入对话之后，
  到对局页面点「重说」。期望：执笔那条回复抽出的卡变「归档」（原因写「来源回复已被丢弃（重说）」），
  新回复抽出的卡「生效」，**生效列表里不再残留来源未知的重复卡**。
  顺带看一次 DevTools Network：这一次点击应当是 1 次正文生成 + 1 次抽取（改动前是 1 + 2）。

## 四、批量执笔的并发（本轮只观察，不加锁）

- [ ] **4.1 批量生成缓冲区的落库结果**：往缓冲区放 3 条以上报幕，点「批量生成」。
  期望仍然是一张一张进对话，但**后台抽取任务是并行的**：请确认事后翻记忆卡时
  没有看到同一主题两张几乎一样的卡、也没有看到水位停在奇怪的值。
  这一项是为了观察「多任务同时写同一会话」在真实使用里到底会不会出问题（现状说明见本轮汇报）：
  批量缓冲区里每条都是「生成 → 插入 → 后台热抽」，**上一个抽取还没跑完，下一条就已经插入**，
  所以同一会话里同时挂着多个抽取任务是设计现状，本轮不加锁。
