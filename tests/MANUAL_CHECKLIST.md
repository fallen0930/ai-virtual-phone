# 手动确认清单

这里只放**自动化测试覆盖不到**的项目。`tests/` 里的用例全部跑在 Node + fake-indexeddb，
`lib/kv-db.ts` 的 `hydrateKvDb()` 被 `typeof window === "undefined"` 守卫短路，
所以「写进真实 IndexedDB、刷新页面后还在」这类事必须由人在浏览器里确认。

约定：每确认一项，把 `[ ]` 改成 `[x]` 并在后面写上确认日期。

- [ ] **1.1 落盘后重读**：在执笔面板抽出一张记忆卡，DevTools → Application → IndexedDB →
  `AiPhoneKvDB.entries`，应能查到键 `narrative:{会话id}:memory:{卡id}`，值为该卡 JSON。
  相关用例：`tests/smoke.test.ts`（Node 里证明过 Dexie 能写读，但不能证明浏览器侧水合链路）。
- [ ] **1.2 刷新后仍在**：F5 刷新对局页面，面板数据里的记忆卡/情感卡/水位/执笔状态全部还在，
  且仍属于同一场对局。
- [ ] **1.3 关标签页再开**：完全关闭页面后重开，1.2 的内容仍然还在（证明不是只活内存缓存）。
- [ ] **1.4 删除对局后不留残数据**：删除一场有执笔数据的对局，刷新后
  IndexedDB 里 `narrative:{被删id}:` 前缀的键全部消失。
  相关用例：`tests/delete-purge.test.ts`（只证明内存缓存层被清，落盘删除需人确认）。

## 三、卡片来源与丢弃归档（本轮新功能）

自动测试覆盖了函数本身的行为，但**引擎在各移除路径上是否真的调用了 `onTurnsDiscarded`**
覆盖不到（测试不允许 import `mixology/engine`）。以下逐条需要在浏览器里真机走一遍：

- [ ] **3.1 重说**：抽出一张卡后点「重说」。期望：旧回复的卡变为「归档」，
  归档原因是「来源回复已被丢弃（重说）」一类文案；新回复抽出的卡为「生效」；
  生效列表里不存在同一来源的两张卡。同时确认小票/机括记住的值照常回滚，没被这次改动带坏。
- [ ] **3.2 回溯**：回溯到中间某条消息。期望：其后所有 assistant 回复抽出的卡归档；
  来源未知的卡（记忆整理/补抽历史/深度抽取产的）一张都不动。
- [ ] **3.3 编辑玩家发言（后续轮次原文齐全，可回放）**：期望一张卡都不归档
  —— 后续轮次是原地重画，消息 id 没变。
- [ ] **3.4 编辑玩家发言（后续有老轮次没存原文，不可回放被截断）**：
  期望被截断掉那些轮的卡归档。
- [ ] **3.5 继续生成 / 重新生成尾部**：期望不归档任何卡（这两条路径纯追加，不删消息）。
- [ ] **3.6 换开场白、按新滤网重洗历史**：期望不归档。
  这是**已知限制**：这两处只换正文、消息 id 不变，卡仍指向那条活着的消息。
  编辑某条助手回复的正文同理（`editMixTurn` 保留 id），也不归档。
- [ ] **3.7 撤回最后一轮**（`undoMixLastRound`）：**目前无入口，无法手测**，
  函数本身的归档行为由 `tests/card-source.test.ts` 覆盖；等 UI 接上后再补手测。
- [ ] **3.8 归档卡的恢复**：在「已归档」筛选下点「恢复生效」。期望：卡片回到「生效」、
  归档原因被清除；来自被丢弃回复的卡旁边应能看到小字提示「该卡来自已被丢弃的回复」。
- [ ] **3.9 竞态**：出一轮回复后立刻（在抽取还没结束时）点重说。
  期望：慢了一步落库的那张卡直接是「归档」，不会以「生效」混进上下文。
- [ ] **3.10 水位不回退**（本轮有意不做，见待办 #24）：重说后关系水位停在旧回复推上去的值，
  确认你接受这个现状；只验证「来源已消失时不再写水位」。

## 四、已知缺口（有意未在本轮处理）

- **#25（优先级高）**：执笔面板「生成正文」这条路的热轨抽取发生在 `insertNarrativeTurn`
  **之前**（`lib/narrative-writer/writer.ts:582`），那一刻这条正文还不是会话里的一条消息，
  拿不到来源消息 id，所以这批卡是**来源未知**。影响：**对执笔生成的回复点「重说」，
  旧回复的卡不会被自动归档**——它们与特调正常回复不同，缺少被追溯的锚点。
  修法是热抽挪到 `insertNarrativeTurn` 之后、用新 turn 的 id 作为来源。
- 补抽历史、深度抽取、记忆整理、手动编辑卡片一律「来源未知」（按设计如此，非缺陷）：
  前三者一次处理的是**一批**消息，无法归属到单条；面板没有手动新增卡片的入口。
- 抽取器不校验情感卡「标签」是否在受控词表内（模型给出词表外的标签会原样入库），
  本轮未处理，写测试时发现的既有现象。
